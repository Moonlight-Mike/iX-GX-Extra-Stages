iX/GX Extra Stages - modding notes
==================================

Everything we learned while making iX/GX Extra Stages for Azure Striker Gunvolt Trilogy Enhanced (Steam,
app 3813350). Written for anyone who wants to mod GX, iX Connect or GV3. It covers what is confirmed, how
we found it, and what is still unknown or untested.

All addresses are RVAs (offsets from game4.exe's load address), from the Steam build current in
November 2026. A game update can move them; the mod checks the original bytes before patching anything,
and so should you.


1. The game files
-----------------
Install folder: steamapps\common\Azure Striker Gunvolt Trilogy Enhanced

- game.exe       the Trilogy launcher (game select).
- game1.exe      Gunvolt 1.    game2.exe  Gunvolt 2.
- game3.exe      Gunvolt 3, but only a small stub: it restarts as game4.exe --GMode=0.
- game4.exe      the real Gunvolt 3 engine. It holds three modes in one exe:
                   --GMode=0  Gunvolt 3 main game
                   --GMode=1  GX main story
                   --GMode=2  iX Connect (internal name "BreakOutlander"; Japanese name "CONNECT X")
                 Full command line: --From=0 --OMode=1 --GMode=N.
                 It can be started directly with the environment variable SteamAppId=3813350 and the
                 install folder as the working directory.
- Data1 / Data2  GV1 / GV2 data (irarc archives, same format as Luminous Avenger iX).
- Data3          GV3 engine data.  DataAddon\1  GX content.

Saves: %USERPROFILE%\Saved Games\INTI CREATES (one folder for the whole Trilogy). The mod copies this
whole folder before changing anything.


2. Working with game4.exe
-------------------------
- The exe on disk is SteamStub-encrypted. Disassembling the file gives garbage. Dump the image from the
  running process instead (ReadProcessMemory over the main module, then set each section's raw
  size/offset equal to its virtual size/address so file offset = RVA).
- Wait until the game has unpacked itself before reading or patching code. The mod polls the bytes at its
  patch sites and only acts once every one of them matches the expected original code.
- Code is x64 MSVC. Useful in a dump:
    * .pdata (exception directory) gives every function's start/end, including chained chunks.
    * RTTI is intact: vtables point back to "Complete Object Locators" whose type descriptor holds the
      class name (".?AVcBsWork86@@" etc.). From a function you can find which class's vtable uses it.
    * Coroutines are named classes too (IceCoArgs... / IceCoLocalImpl@...co_Act_Attack02@cBsWork86...),
      so boss attack names can be read straight out of RTTI.
- Tools we used: Python + capstone for disassembly and scans, Frida for runtime logging (exceptions,
  process exit backtraces, hooks), C# (csc from .NET Framework 4, x64) for the patcher.
- Frida tips: Interceptor hooks on code are fine; MemoryAccessMonitor and hardware watchpoints that write
  in their handler crashed the game. Detaching can hang, so stop helper processes by PID.
- Process gotcha: a closed game4 can stay listed (HasExited = true) while Steam or Game Bar still holds a
  handle to it. Always skip exited processes when looking for the game, or you will attach to a dead
  one and nothing will happen.


3. Data formats (GV3 engine, also used by GX)
---------------------------------------------
Path hash (folder and file names, per path component), unsigned 32-bit:
    h = 0xCDE723A5;  for each byte c:  h = (h + c) * 0x8D
  Examples: GV3 = 8e90ad39, GVX = 8e90c19a, Addon = 18db3b43, Text = ba8a7e6e, UI = 73691a3f.
  The same hash is used for text keys, e.g. "StageName31" = 0x37e604e2, "StageName32" = 0x37e6056f.

File index: embedded in game4.exe, not in a separate file. 0x38-byte records from 0x1400000 to
  0x1626fc0, string pool at 0x1626fc0. Record: +0 entry hash, +0xC pack path offset, +0x10 type
  constant (hash of the extension, e.g. bin = 9319757a, osb = 95488689), +0x14 offset in pack,
  +0x18/+0x1C sizes, +0x24 u16 type, +0x26 u16 addon number (n-1 -> DataAddon\n).

Cipher: only sound entries are encrypted. Key = 64-bit hash of "%08x/GV3.oss" (entry hash), seed
  0xA1B34F58CAD705B2, h = (h + (signed char)c) * 0x8D; byte i: p = c ^ (h >> (i & 31)); h = (h + c) * 0x8D.
  Compressed entries (size != unpacked size): decrypt, then u32 unpacked size + zlib.

Text tables: JSON with a nibble-rolling XOR (key 570FAC7E6923). They contain \' escapes that break
  strict JSON parsers - replace them before parsing. Each language is a separate file; pick the
  language by content.

Save files: two cipher passes (keys gv3encrypt_key_02, then _01) with a 0x400-byte header.


4. Stage ids and names
----------------------
A "stage id" is the number the game uses everywhere (menu, loader, save records). The text key for a
stage's name is StageName<id + 1>.

  0-15   GX story missions (id 10 is a blank slot, not in any menu; 14 = Sunrise Throne)
  16-29  GX Secret Missions (menu order isn't id order), including:
  28     Secret Mission 15 = Boss Rush
  29     Slothful Experiments
  30     Third Revenger   (StageName31, JP 双極の紫背者)  boss: Nova    (GV3 stage)
  31     Grand Master     (StageName32, JP 新世界の王)    boss: Asimov  (GV3 stage)

Stages 30 and 31 are GV3's two secret-boss stages (added in GV3 updates 1.3.0 and 1.4.0). Their maps,
scripts, bosses and rank rows all exist in GX, but GX's menu never lists them. Forcing the stage id at
Dispatch loads both and they play fully, as GV or as Copen.

iX Connect's own five stages are ids 1, 2, 3, 4 and 13 (Sunrise Palace).


5. Mode flag
------------
dword at 0x1e1ba08: 1 = GX main story, 0 = iX Connect. (The byte at 0x1dcf151 is a different flag and
is 0 in both modes - don't use it to tell them apart.)


6. Mission lists (what the mission select shows)
------------------------------------------------
GX list:          0x1ccc0e0 .. 0x1ccc680  (30 entries)
iX Connect list:  0x1ccc680 .. 0x1ccc770  (5 entries, directly after the GX list)

Entry, 0x30 bytes:
  +0x08  u32 stage id
  +0x0C  u8 stage id, +0x0D u8 chapter (menu page group)
  +0x18  u32 name hash (text key StageNameNN)
  +0x1C  u32 banner sprite sheet hash
  +0x20  u32 banner sprite hash  (= hash of a prefix + "%02d" of id+1 for 27 of the 30 entries)
  +0x28  u32 map name hash ("stNN")
  +0x00  is NOT the banner/icon (tested).

Each mode looks entries up by stage id through "lea reg,[list]" / "lea reg,[list end]" pairs:
  GX: 9 pairs   (0xdb3718/0xdb3734, 0xe6cafe/0xe6cb17, 0xe6f561/0xe6f57d, 0xe6fa08/0xe6fa1c,
                 0xe7088e/0xe708aa, 0xe72d23/0xe72d2a, 0xe74518/0xe74526 menu builder,
                 0xe75caa/0xe75cc6, 0xe78083/0xe7809f)
  iX: 9 pairs   (0xdb3751/0xdb3758, 0xe6cb30/0xe6cb37, 0xe6f594/0xe6f59b, 0xe6fa33/0xe6fa3a,
                 0xe708c2/0xe708c9, 0xe72d15/0xe72d1c, 0xe745d9/0xe745e0 menu builder,
                 0xe75ce0/0xe75ce7, 0xe780b6/0xe780bd)
  A failed lookup falls back to GX entry 0.

The mod builds one 32-entry list (GX's 30 + stages 30 and 31) in memory it allocates near the exe, and
points all 18 pairs at it, so both modes see the same list. The two new entries are copies of the
stage 26 entry with the id, chapter 11 (the Boss Rush page) and name hash changed.

Banners: the computed banner sprites for ids 30/31 are blank - GV3's stages have no banner in GX. The mod
copies Boss Rush's +0x1C/+0x20 pair (920abed3 / 5078ff37, the Gunvolt + Copen banner) into both.


7. Menu builders and unlock rules
---------------------------------
GX (main story), around 0xe74530: adds an entry only if bit <stage id> is set in the unlock bitmask
  (0x1dfb8c0, pointed to by r14). Ids 30/31 never get a bit, so the check was rewritten to let ids >= 30
  through:
    original  0f b6 4b 0c 8b d1 83 e2 1f 8b c1 48 c1 e8 05 41 8b 04 86 0f a3 d0 73 0d
    patched   0f b6 4b 0c 83 f9 1e 73 0f 8b c1 c1 e8 05 41 8b 04 86 0f a3 c8 73 0e 90
  (movzx ecx,[rbx+0xc]; cmp ecx,30; jae add; ...; bt eax,ecx; jae skip)

GX paging (0xe746e0): an entry joins a page only if its chapter (+0x0D) equals the page index. On a
  save that hasn't unlocked every chapter, the pages shift, so each later entry gets a page of its own.
  On a finished save they share the Boss Rush page. Left unchanged.

iX Connect, 0xe745eb: ids 1-4 are always added; id 13 (Sunrise Palace) only after the other four are
  cleared. The mod replaces "sub ecx,1; je add" (83 e9 01 74 54) with "cmp ecx,<id>; jne add"
  (83 f9 <id> 75 54), which adds everything except one hidden id (14, or none = 0xff).

When the stages unlock in normal GX play: all Secret Missions unlock at the end of the story (staff
  roll sets bit 2 of 0x1dfb6d0 and event flag 0x111).


8. Stage loading: descriptor rows and stage logic
-------------------------------------------------
Each mode has a table of 32-byte rows, one per stage area:
  iX:  0x170cbd0, 39 rows (0x27).   GX: 0x170d0b0, 78 rows (0x4e).
  Row: +0x00 map hash, +0x08 script hash, +0x10/+0x18/+0x19/+0x1C stage/area fields
       (+0x18 = stage, +0x19 = area). The row number is also stored on the stage object (+0x189).

iX's table only has maps for its five stages; every other row is blank, and loading one crashes. Other
row-indexed tables in the game use GX's row numbers, so rows must not be shifted.

The mod builds a 78-row table: iX's rows with blank map hashes filled from GX's matching rows (only when
the stage/area at +0x18 matches), then GX's rows 39-77 at the same row numbers. Rows 36-38 are the
conflict: iX uses them for its three-area Sunrise Palace (stage 13), GX for Sunrise Palace 3's two areas
and Sunrise Throne's first area. That is why the app has a switch, and why Sunrise Throne (id 14) is
hidden while iX's Sunrise Palace is in use.

Patches for the table: 31 iX-branch "lea reg,[iX table + field]" sites redirected (fields 0, 8, 0x10,
0x18, 0x19, 0x1C), and 16 iX row limits raised from 0x27 to 0x4e (e.g. cmp al,0x27 at 0xa3fd21,
0xd8c910, 0xd9e27a, ...; full list in src\IxGxExtraStages.cs).

Stage logic: a table of one pointer per row (iX 0x1716f20, GX 0x1716cb0). Rows without logic point at
0x1c99250 (null logic). The combined table takes iX's pointer where it is real and GX's otherwise. The
only read is "mov rcx,[rcx+rbp*8+disp32]" at 0xb001cf; its disp32 is pointed at the new table.


9. Dispatch, difficulty and forcing a stage
-------------------------------------------
At Dispatch the selected mission sits in a structure at [scene+0x290]:
  +0x118  selected stage id    +0x11C  selected difficulty (0 normal, 1 hard, 2 very hard)
Stage load (shared by both modes): 0xdb05f0 / 0xdb0642 read the stage id; replacing those loads with a
  constant loads any stage from any menu entry (how the first Grand Master tests were done). The id is
  written to the stage object at 0xdb05fe.
Difficulty: 0xdb060b (mov ecx,[rax+0x11c]) and 0xdb061e (mov r8d,[rax+0x11c]) copy it into the stage
  object (+0x664) and the save. iX Connect always leaves it at 0, so the mod replaces those two loads
  with "mov ecx,N" / "mov r8d,N". GX's hard/very hard rules then apply in iX Connect.
  Difficulty names: EN STANDARD / DEMANDING / MERCILESS TASK; JP T A S K / SEVERE TASK / RECKLESS TASK.


10. The stage object and players
--------------------------------
Stage object pointer: 0x1dce380.
  +0x188  stage id         +0x189  descriptor row
  +0x540  player class: 1 = cPlWorkGV (Gunvolt), 2 = cPlWorkRageGV, 3 = cPlWork00 (Copen)
  +0x620  Copen's player slot      +0x628  Gunvolt's player slot
  +0x664  difficulty
Playing as Copen, +0x628 is always 0. Any code that reads it without a null check will crash.

Boss classes are cBsWorkNN. Asimov (Grand Master) is cBsWork86. cBsWork85 is a near copy of it in the
code next to it and is most likely Nova (not confirmed in game).


11. The Grand Master crash and the fix
--------------------------------------
Symptom: as Copen, the game sometimes closed to the desktop in the middle of the Grand Master fight,
with no error and no Windows Error Report.

Found with a Frida logger that waits for game4, then logs exceptions and exit backtraces during play:
  Asimov's co_Act_Attack02 (pattern 4, coroutine 0x90cad0) calls 0x8ed8a0, which does
    mov rcx,[rax+0x628]            ; rax = stage object -> Gunvolt's slot
    cmp dword ptr [rcx+0xc4],4     ; Gunvolt's state == 4 ?
  With no Gunvolt the slot is null -> access violation at 0x8ed97f.

Fix: the 23 bytes at 0x8ed975 become a jmp to a guard in the allocated block (which must be RWX):
    mov rcx,[rax+0x628]; xorps xmm6,xmm6; test rcx,rcx; jz notFour
    cmp dword [rcx+0xc4],4; jne notFour; jmp 0x8ed98c (continue)
    notFour: jmp 0x8edac2 (the game's own "state != 4" path)
The "state != 4" branch only does a distance check and sets a flag ([obj+0x61e]). It is not the grab
(co_Act_PL_Bind_Throw starts at 0x8fda00), so the fight plays normally. Tested: the guard caught a
missing player about 60 times in 10 seconds with no crash; over 6 minutes idle in the fight including a
death and Anthem without a crash (the unfixed game crashed within about a minute).

Other bosses: a scan of every read of Gunvolt's slot through the stage object found 92 reads, 26 of them
null-checked. In the boss classes the only unchecked one is Asimov's. Nova's code (cBsWork85) and
everything it calls directly (5 levels deep) never reads Gunvolt's slot. Virtual calls were not followed.
Playtesting Nova as Copen has not crashed. The remaining unchecked reads are in player, HUD and effect
code.


12. How the patcher works
-------------------------
- Finds a live game4 process, opens it (VM read/write/operation + query).
- Waits until every patch site holds its original bytes (or bytes it wrote itself).
- Allocates one block (0x2000 bytes, RWX) within 2 GB below the exe so rel32 leas can reach it, and
  writes: descriptor table at +0, logic table at +0xA00, mission list at +0x1000, Asimov guard at
  +0x1800.
- Installs the Asimov guard as soon as the game is up, whatever the checkbox says.
- The checkbox applies or reverts all the list/table/menu patches; the switch rewrites rows 36-38;
  the difficulty picker swaps the two Dispatch loads.
- On close it writes the original code back (the block stays allocated, harmlessly), so the game is
  normal again and a later patcher finds original bytes.
- Before the first change of a session it copies the save folder into "save backups" next to the app.
- Switching the stages off during a stage can break that stage's results screen, so leave them on
  until you are back on the menu.


13. GX unlocks (found along the way)
------------------------------------
- Unlock flags live in the save (live slot +0x48c4, save file body +0x440c), 59 entries mapped by the
  table at 0x14813f0. Availability check at 0x553570.
- Writers in 0xdb33f0: staff roll -> Harder/Better, Medley, Lumen off, Lola off; all 15 story stages
  cleared on Hard -> Eternalizer, Clock Darter, Icarus Wing, Infinity Trigger; same on Very Hard ->
  Lost iX, Gunvolt Chronicles.
- Songs unlock when they actually play (cGV3_BGMController). Copen's EX weapons come from a factory
  table of 19 create functions at 0x1c72db0 (ids 4-10 iX Connect, 11-18 GX).
- Abilities table: records of 0x34 bytes at 0x1c54904; song abilities at 0x1c55d54.
- GV3 item / Image Pulse table: 538 records of 0x74 bytes at 0x1c74144, strings at 0x1c8350c.
  Passive 1-150 and 400-499, Summon 201-399, Song 151-200.


14. Things that did not work or are unproven
--------------------------------------------
- No way was found to reach Grand Master in GX with normal input only. GV3's warp checks need Gunvolt
  (not Copen), the staff-roll flag, and specific Image Pulses equipped, which GX can't give.
- Boss Rush's rows reuse other stages' scripts; Nova is not in Boss Rush by table.
- Not tested: clearing Third Revenger / Grand Master from GX's menu (results screen, score saving).
- Not confirmed in game: cBsWork85 = Nova.

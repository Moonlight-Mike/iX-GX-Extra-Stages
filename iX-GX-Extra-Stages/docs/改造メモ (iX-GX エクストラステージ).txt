iX/GX エクストラステージ　改造メモ
=================================

Steam版「Azure Striker Gunvolt Trilogy Enhanced」（アプリID 3813350）用の「iX/GX エクストラステージ」を
作る過程で分かったことをすべてまとめました。GX、CONNECT X、ガンヴォルト３を改造したい方向けです。
確認済みの内容、その調べ方、まだ分かっていないこと・未テストのことを記載しています。

アドレスはすべて RVA（game4.exe の読み込みアドレスからのオフセット）で、2026年11月時点のSteam版のものです。
アップデートで変わる可能性があります。このツールは書き換え前に元のバイト列を確認しています。
皆さんも同じようにしてください。


1. ゲームのファイル
-------------------
インストール先：steamapps\common\Azure Striker Gunvolt Trilogy Enhanced

- game.exe       トリロジーのランチャー（タイトル選択）。
- game1.exe      ガンヴォルト１。　game2.exe　ガンヴォルト２。
- game3.exe      ガンヴォルト３…ですが中身は小さな起動用プログラムで、game4.exe --GMode=0 として起動し直します。
- game4.exe      ガンヴォルト３本体のエンジン。１つの exe に３つのモードがあります：
                   --GMode=0  ガンヴォルト３本編
                   --GMode=1  GX本編
                   --GMode=2  CONNECT X（内部名 "BreakOutlander"、英語名 iX Connect）
                 コマンドライン全体：--From=0 --OMode=1 --GMode=N
                 環境変数 SteamAppId=3813350 を設定し、作業フォルダをインストール先にすれば直接起動できます。
- Data1 / Data2  GV1 / GV2 のデータ（irarc形式。ルミナスアヴェンジャーiXと同じ）。
- Data3          GV3エンジンのデータ。　DataAddon\1　GXのデータ。

セーブ：%USERPROFILE%\Saved Games\INTI CREATES（トリロジー全体で１フォルダ）。
ツールは何かを変更する前にこのフォルダ全体をコピーします。


2. game4.exe の扱い方
---------------------
- ディスク上の exe は SteamStub で暗号化されているため、そのまま逆アセンブルしても意味のないデータになります。
  起動中のプロセスからイメージをダンプしてください（メインモジュールを ReadProcessMemory で読み、
  各セクションの raw size/offset を virtual size/address と同じにすると、ファイルオフセット = RVA になります）。
- コードの読み書きは、ゲームが自身を展開し終えてからにしてください。ツールは書き換え箇所のバイト列を
  定期的に確認し、すべてが元のコードと一致してから動作します。
- コードは x64 の MSVC 製。ダンプで役立つもの：
    * .pdata（例外ディレクトリ）で全関数の開始・終了位置が分かります（チェーンされた分割部分も含む）。
    * RTTI が残っています。vtable の直前から「Complete Object Locator」→型情報をたどるとクラス名
      （".?AVcBsWork86@@" など）が分かります。関数からその関数を使う vtable のクラスも探せます。
    * コルーチンも名前付きのクラスなので（IceCoLocalImpl@...co_Act_Attack02@cBsWork86... など）、
      ボスの攻撃名を RTTI から直接読めます。
- 使用ツール：Python + capstone（逆アセンブル・検索）、Frida（実行時のログ：例外、終了時のバックトレース、フック）、
  C#（.NET Framework 4 の csc、x64）でツール本体。
- Frida の注意：コードへの Interceptor フックは問題なし。MemoryAccessMonitor や、ハンドラ内で書き込みをする
  ハードウェアウォッチポイントはゲームが落ちました。デタッチが固まることがあるので、補助プロセスは PID 指定で終了してください。
- プロセスの注意：終了した game4 が、Steam やゲームバーがハンドルを持っている間、一覧に残ることがあります
  （HasExited = true）。ゲームを探すときは終了済みのプロセスを必ず除外してください。
  そうしないと終了済みのプロセスに接続して、何も起きません。


3. データ形式（GV3エンジン、GXも同じ）
-------------------------------------
パスハッシュ（フォルダ名・ファイル名、パスの各要素ごと）、32ビット符号なし：
    h = 0xCDE723A5;  各バイト c について  h = (h + c) * 0x8D
  例：GV3 = 8e90ad39、GVX = 8e90c19a、Addon = 18db3b43、Text = ba8a7e6e、UI = 73691a3f。
  テキストのキーも同じハッシュです。例："StageName31" = 0x37e604e2、"StageName32" = 0x37e6056f。

ファイル索引：別ファイルではなく game4.exe に埋め込まれています。0x1400000〜0x1626fc0 に 0x38 バイトのレコード、
  文字列プールは 0x1626fc0。レコード：+0 エントリハッシュ、+0xC パックのパス位置、+0x10 種類（拡張子のハッシュ。
  bin = 9319757a、osb = 95488689 など）、+0x14 パック内の位置、+0x18/+0x1C サイズ、+0x24 u16 種類、
  +0x26 u16 アドオン番号（n-1 → DataAddon\n）。

暗号：暗号化されているのはサウンドのみ。キー = "%08x/GV3.oss"（エントリハッシュ）の64ビットハッシュ、
  初期値 0xA1B34F58CAD705B2、h = (h + (signed char)c) * 0x8D。i バイト目：p = c ^ (h >> (i & 31))、h = (h + c) * 0x8D。
  圧縮エントリ（サイズ ≠ 展開後サイズ）：復号後、u32 展開後サイズ + zlib。

テキスト表：ニブル単位のローリングXOR（キー 570FAC7E6923）をかけた JSON。\' というエスケープが含まれており、
  厳密な JSON パーサーでは読めないので、事前に置き換えてください。言語ごとに別ファイルなので、中身で判別します。

セーブファイル：２段階の暗号（キー gv3encrypt_key_02、次に _01）、0x400 バイトのヘッダー付き。


4. ステージ番号と名前
---------------------
「ステージ番号」はゲーム内のあらゆる場所（メニュー、ローダー、セーブの記録）で使われる番号です。
ステージ名のテキストキーは StageName<番号 + 1> です。

  0-15   GX本編のミッション（10 は空きで、どのメニューにもありません。14 = 太陽宮玉座）
  16-29  GXのスペシャルミッション（メニューの順番は番号順ではありません）。うち：
  28     スペシャルミッション１５ = ボスラッシュ
  29     Slothful Experiments（英語名）
  30     双極の紫背者（StageName31、英語 Third Revenger）　ボス：紫電（Nova）　（GV3のステージ）
  31     新世界の王（StageName32、英語 Grand Master）　　　ボス：アシモフ　　（GV3のステージ）

30 と 31 はガンヴォルト３の隠しボスステージ２つです（GV3 のアップデート 1.3.0 / 1.4.0 で追加）。マップ、スクリプト、
ボス、ランク表はすべてGXにも存在しますが、GXのメニューには一度も表示されません。出撃時にステージ番号を
差し替えると、ガンヴォルトでもコピンでも、どちらも最後まで遊べる状態で読み込まれます。

CONNECT X 本来の５ステージは 1、2、3、4、13（太陽宮）です。


5. モードの判別
---------------
0x1e1ba08 の dword：1 = GX本編、0 = CONNECT X。（0x1dcf151 のバイトは別のフラグで、どちらのモードでも 0 なので、
判別には使えません。）


6. ミッション一覧（ミッション選択の中身）
---------------------------------------
GXの一覧：        0x1ccc0e0 〜 0x1ccc680（30件）
CONNECT Xの一覧： 0x1ccc680 〜 0x1ccc770（5件、GXの一覧の直後）

1件 0x30 バイト：
  +0x08  u32 ステージ番号
  +0x0C  u8 ステージ番号、+0x0D u8 章（メニューのページ分け）
  +0x18  u32 名前のハッシュ（テキストキー StageNameNN）
  +0x1C  u32 バナーのスプライトシートのハッシュ
  +0x20  u32 バナーのスプライトのハッシュ（30件中27件は 接頭辞 + "%02d"（番号+1）のハッシュ）
  +0x28  u32 マップ名のハッシュ（"stNN"）
  +0x00  はバナー／アイコンではありません（テスト済み）。

各モードは "lea reg,[一覧]" / "lea reg,[一覧の終わり]" の組でステージ番号から検索します：
  GX：9組　 (0xdb3718/0xdb3734, 0xe6cafe/0xe6cb17, 0xe6f561/0xe6f57d, 0xe6fa08/0xe6fa1c,
            0xe7088e/0xe708aa, 0xe72d23/0xe72d2a, 0xe74518/0xe74526 メニュー作成,
            0xe75caa/0xe75cc6, 0xe78083/0xe7809f)
  iX：9組　 (0xdb3751/0xdb3758, 0xe6cb30/0xe6cb37, 0xe6f594/0xe6f59b, 0xe6fa33/0xe6fa3a,
            0xe708c2/0xe708c9, 0xe72d15/0xe72d1c, 0xe745d9/0xe745e0 メニュー作成,
            0xe75ce0/0xe75ce7, 0xe780b6/0xe780bd)
  見つからなかった場合はGXの0件目が使われます。

ツールは、exe の近くに確保したメモリに32件の一覧（GXの30件 + ステージ30・31）を作り、18組すべてをそこへ向けるので、
両モードが同じ一覧を使います。追加の２件はステージ26の項目をコピーし、番号、章 11（ボスラッシュのページ）、
名前のハッシュを書き換えたものです。

バナー：番号30/31用に計算されるバナーのスプライトは空です。GV3のステージにはGX用のバナーがありません。
ツールはボスラッシュの +0x1C/+0x20（920abed3 / 5078ff37、ガンヴォルトとコピンのバナー）を両方にコピーしています。


7. メニューの作成処理と解放条件
-------------------------------
GX本編（0xe74530 付近）：解放ビットマスク（0x1dfb8c0、r14 が指す）でステージ番号のビットが立っている項目だけを
  追加します。30/31 にはビットが立たないので、30以上は通すように書き換えました：
    元      0f b6 4b 0c 8b d1 83 e2 1f 8b c1 48 c1 e8 05 41 8b 04 86 0f a3 d0 73 0d
    変更後  0f b6 4b 0c 83 f9 1e 73 0f 8b c1 c1 e8 05 41 8b 04 86 0f a3 c8 73 0e 90
  （movzx ecx,[rbx+0xc]; cmp ecx,30; jae 追加; ...; bt eax,ecx; jae 飛ばす）

GXのページ分け（0xe746e0）：項目の章（+0x0D）がページ番号と一致したときだけ、そのページに入ります。
  すべての章が解放されていないセーブではページがずれ、後ろの項目がそれぞれ別のページになります。
  クリア済みのセーブではボスラッシュのページにまとまります。ここは変更していません。

CONNECT X（0xe745eb）：1〜4 は常に追加、13（太陽宮）は他の４つをクリアした後だけ。ツールは
  "sub ecx,1; je 追加"（83 e9 01 74 54）を "cmp ecx,<番号>; jne 追加"（83 f9 <番号> 75 54）に置き換え、
  １つの番号（14、または 0xff = なし）以外をすべて追加します。

通常のGXでの解放：スペシャルミッションはストーリークリア時にすべて解放されます
  （スタッフロールで 0x1dfb6d0 のビット2 とイベントフラグ 0x111 が立ちます）。


8. ステージの読み込み：ステージ表とステージ処理
----------------------------------------------
各モードに、ステージのエリアごとに 32 バイトの行を持つ表があります：
  iX：0x170cbd0、39行（0x27）。　GX：0x170d0b0、78行（0x4e）。
  行：+0x00 マップのハッシュ、+0x08 スクリプトのハッシュ、+0x10/+0x18/+0x19/+0x1C ステージ・エリアの値
     （+0x18 = ステージ、+0x19 = エリア）。行番号はステージオブジェクト（+0x189）にも保存されます。

iX の表には５ステージ分のマップしかなく、他の行は空で、読み込むと落ちます。ゲーム内の他の行番号ベースの表は
GXの行番号を使っているので、行をずらしてはいけません。

ツールは78行の表を作ります：iX の行（空のマップハッシュは、+0x18 のステージ・エリアが一致する場合のみGXの同じ行から補完）、
その後にGXの39〜77行を同じ行番号で配置。36〜38行が衝突します。iX はここを３エリアの太陽宮（ステージ13）に、
GX は太陽宮３の２エリアと太陽宮玉座の最初のエリアに使っています。そのためツールに切り替えスイッチがあり、
iX の太陽宮を使っている間は太陽宮玉座（14）を隠しています。

表のための書き換え：iX 側の "lea reg,[iX の表 + フィールド]" 31箇所の参照先を変更（フィールド 0、8、0x10、0x18、0x19、0x1C）、
iX 側の行数の上限16箇所を 0x27 から 0x4e に変更（0xa3fd21、0xd8c910、0xd9e27a の cmp al,0x27 など。
全一覧は src\IxGxExtraStages.cs）。

ステージ処理：行ごとに１つのポインタを持つ表（iX 0x1716f20、GX 0x1716cb0）。処理のない行は 0x1c99250（空の処理）を指します。
統合した表は、iX に本物の処理がある行は iX のもの、それ以外はGXのものを使います。読み出しは 0xb001cf の
"mov rcx,[rcx+rbp*8+disp32]" の１箇所だけで、その disp32 を新しい表に向けています。


9. 出撃、難易度、ステージの差し替え
-----------------------------------
出撃時、選択中のミッションは [scene+0x290] の構造体にあります：
  +0x118  選択中のステージ番号　　+0x11C  選択中の難易度（0 通常、1 ハード、2 ベリーハード）
ステージの読み込み（両モード共通）：0xdb05f0 / 0xdb0642 でステージ番号を読みます。ここを定数に置き換えると、
  どのメニュー項目からでも任意のステージを読み込めます（新世界の王の最初のテストはこの方法）。番号は 0xdb05fe で
  ステージオブジェクトに書き込まれます。
難易度：0xdb060b（mov ecx,[rax+0x11c]）と 0xdb061e（mov r8d,[rax+0x11c]）がステージオブジェクト（+0x664）と
  セーブにコピーします。CONNECT X では常に 0 なので、ツールはこの２箇所を "mov ecx,N" / "mov r8d,N" に置き換えます。
  するとGXのハード／ベリーハードのルールが CONNECT X でも適用されます。
  難易度名：日本語 T A S K / SEVERE TASK / RECKLESS TASK、英語 STANDARD / DEMANDING / MERCILESS TASK。


10. ステージオブジェクトとプレイヤー
------------------------------------
ステージオブジェクトのポインタ：0x1dce380。
  +0x188  ステージ番号      +0x189  ステージ表の行
  +0x540  プレイヤーの種類：1 = cPlWorkGV（ガンヴォルト）、2 = cPlWorkRageGV、3 = cPlWork00（コピン）
  +0x620  コピンのプレイヤー枠      +0x628  ガンヴォルトのプレイヤー枠
  +0x664  難易度
コピンで遊んでいる間、+0x628 は常に 0 です。ここを null チェックなしで読むコードがあると落ちます。

ボスのクラスは cBsWorkNN。アシモフ（新世界の王）は cBsWork86。cBsWork85 はそのすぐ隣にあるほぼ同じ作りのクラスで、
紫電（Nova）である可能性が高いです（ゲーム内では未確認）。


11. 新世界の王で落ちる不具合とその修正
--------------------------------------
症状：コピンで新世界の王を戦っていると、戦闘中にエラーも Windows エラー報告もなくデスクトップに戻ることがありました。

Frida のロガー（game4 の起動を待ち、プレイ中の例外と終了時のバックトレースを記録）で特定：
  アシモフの co_Act_Attack02（パターン4、コルーチン 0x90cad0）が 0x8ed8a0 を呼び、そこで
    mov rcx,[rax+0x628]            ; rax = ステージオブジェクト → ガンヴォルトの枠
    cmp dword ptr [rcx+0xc4],4     ; ガンヴォルトの状態 == 4 ?
  ガンヴォルトがいないと枠が null → 0x8ed97f でアクセス違反。

修正：0x8ed975 の23バイトを、確保したメモリ（RWX が必要）内のガードへの jmp に置き換え：
    mov rcx,[rax+0x628]; xorps xmm6,xmm6; test rcx,rcx; jz notFour
    cmp dword [rcx+0xc4],4; jne notFour; jmp 0x8ed98c（続き）
    notFour: jmp 0x8edac2（ゲーム本来の「状態 != 4」の処理）
「状態 != 4」の処理は距離の確認とフラグ（[obj+0x61e]）の設定だけで、つかみ攻撃ではありません
（co_Act_PL_Bind_Throw は 0x8fda00 から）。そのため戦闘は普通に進みます。テスト：ガードは10秒間に約60回
プレイヤー不在を検出し、落ちませんでした。戦闘中に死亡やアンセムを含めて6分以上放置しても落ちませんでした
（修正前は約1分以内に落ちていました）。

他のボス：ステージオブジェクト経由でガンヴォルトの枠を読む箇所を全部調べたところ92箇所、うち26箇所は null チェックあり。
ボスのクラスでチェックなしはアシモフの１箇所だけでした。紫電のコード（cBsWork85）と、そこから直接呼ばれる関数（5段階まで）は
ガンヴォルトの枠を読みません。仮想関数呼び出しは追っていません。コピンでの紫電戦のプレイテストでも落ちていません。
残りのチェックなしの読み出しは、プレイヤー、HUD、エフェクトのコードです。


12. ツールの仕組み
------------------
- 実行中の game4 プロセスを見つけて開きます（VM 読み書き・操作 + 情報取得）。
- すべての書き換え箇所が元のバイト列（または自分が書いたバイト列）になるまで待ちます。
- exe の下側 2GB 以内に 0x2000 バイトのメモリ（RWX）を１つ確保し（rel32 の lea が届くように）、次を書き込みます：
  +0 にステージ表、+0xA00 にステージ処理の表、+0x1000 にミッション一覧、+0x1800 にアシモフ用のガード。
- アシモフ用のガードは、チェックの有無に関係なくゲームの起動を確認した時点で入れます。
- チェックボックスで一覧・表・メニューの書き換えをすべて適用／元に戻し、スイッチで36〜38行を書き換え、
  難易度の選択で出撃時の２箇所を差し替えます。
- 閉じると元のコードを書き戻します（確保したメモリは残りますが無害です）。ゲームは元に戻り、
  次に起動したツールも元のバイト列を確認できます。
- その回で最初に何かを変更する前に、セーブフォルダをツールの隣の「セーブバックアップ」にコピーします。
- ステージ中にステージ追加をオフにすると、そのステージの結果画面が壊れることがあるので、メニューに戻るまでオンのままにしてください。


13. GXの解放要素（調査中に判明）
-------------------------------
- 解放フラグはセーブにあります（実行中のスロット +0x48c4、セーブファイル本体 +0x440c）。59件で、0x14813f0 の表で対応付け。
  使えるかどうかの確認は 0x553570。
- 書き込みは 0xdb33f0：スタッフロール → Harder/Better、メドレー、ルーメン オフ、ロロ オフ。本編15ステージをすべてハードで
  クリア → Eternalizer、Clock Darter、Icarus Wing、Infinity Trigger。ベリーハードで同じ → Lost iX、Gunvolt Chronicles。
  （英語名。日本語名は未確認）
- 歌は実際に流れたときに解放されます（cGV3_BGMController）。コピンの EX ウェポンは 0x1c72db0 の19個の生成関数の表から
  （4〜10 が CONNECT X、11〜18 がGX）。
- アビリティの表：0x1c54904 に 0x34 バイトのレコード。歌のアビリティは 0x1c55d54。
- GV3 のアイテム／イメージパルスの表：0x1c74144 に 0x74 バイトのレコードが538件、文字列は 0x1c8350c。
  パッシブ 1〜150 と 400〜499、スキル（召喚）201〜399、歌 151〜200。


14. うまくいかなかったこと・未確認のこと
